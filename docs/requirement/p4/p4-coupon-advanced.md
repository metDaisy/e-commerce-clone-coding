# P4 Coupon Advanced (쿠폰 심화 과정)

기본 업무 정책은 [P4 Coupon Policy](p4-policy.md), 데이터 모델과 공통 API는 [Coupon API](p4-coupon.md)를 따른다. 이 문서는 기본 과정에 포함하지 않는 심화 정책과 Amazon 비교를 정의한다.

이 문서에서 정책을 다음과 같이 구분한다.

- `유사`: Amazon Seller 쿠폰에서 확인되는 정책과 방향이 같다.
- `부분 유사`: Amazon에도 유사 기능이 있지만 마켓·프로그램별 차이가 있거나, 현재 P4가 단순화한 정책이다.
- `비유사`: 현재 P4가 Amazon의 운영 절차를 생략하거나 다르게 정한 정책이다.
- `확인 필요`: 공개 자료만으로 Amazon의 세부 동작이나 데이터 구조를 확정하기 어렵다.

## 1. 정책 비교 요약

| 항목 | Amazon에서 확인되는 운영 | 현재 P4 | 구분 |
|---|---|---|---|
| 적용 상품 | 판매자가 상품을 선택하고 쿠폰 하나에 최대 200개 ASIN을 연결 | `targetOfferIds` 1~200개 | 유사 |
| 할인 방식 | 퍼센트 또는 정액 할인 | `PERCENTAGE` 또는 `FIXED_AMOUNT`, KRW 정수 | 유사. 통화·저장 형식은 프로젝트 정책 |
| 상품 자격 검증 | 판매 이력, 기준 가격, 최근 최저가, 할인율 등 검증 | 기본 과정에서는 검증하지 않고 자동 적용 | 비유사 |
| 플랫폼 검토 | 제출 후 검토를 거쳐 활성화 | 판매자 쿠폰 검토·승인 없음 | 비유사 |
| 퍼센트 할인 범위 | 미국 쿠폰 정책에서 5~50%가 확인됨 | 5~50% | 유사 |
| 기간 | 기간 한정 쿠폰 운영 | `validFrom`, `validUntil`, 최대 30일 | 부분 유사. 최대 30일은 프로젝트 정책이며 Amazon 공통 정책으로 확정하지 않음 |
| 고객 Clip | 고객이 쿠폰을 Clip한 후 주문에 적용 | `CouponClip`과 `POST .../clip` | 유사 |
| 고객군 | Prime Member Coupons 등 특정 프로그램이 존재 | 신규·재구매·등급 등 고객군 선택은 심화 | 부분 유사 |
| 주문별 적용 수량 | 조건에 따라 퍼센트 쿠폰은 최대 5개 상품, 정액 쿠폰은 1개 상품 적용 | 서로 다른 쿠폰 최대 5개. 쿠폰별로 퍼센트 5개, 정액 1개 상품 적용 | 부분 유사. 세부 조건은 Amazon 프로그램별 확인 필요 |
| 사용자별 사용 제한 | 쿠폰 생성 시 1인 1회 제한을 선택할 수 있음 | 기본 과정은 사용자별 최대 1회 | 부분 유사. P4는 단순화한 기본값 |
| 예산 | 예산을 설정하고 80% 소진 시 노출을 중단하며, 이미 적용된 주문 때문에 초과될 수 있음 | 예산·확정·예약 금액과 동시성 처리를 심화로 보류 | 부분 유사 |
| 중복 할인 | 여러 절약 수단이 함께 제공될 수 있어 의도하지 않은 중복 할인을 주의 | 서로 다른 상품의 쿠폰 최대 5개는 허용하고, 동일 상품의 쿠폰 중첩은 금지 | 부분 유사. 조합별 규칙은 확인 필요 |
| 활성 쿠폰 수정 | 활성 쿠폰 할인액을 상향 수정할 수 있다는 Amazon 공지가 있음 | `validUntil`만 수정 가능 | 비유사 |
| 통계 | Seller Central 쿠폰 대시보드에서 운영 현황 확인 | 통계 API와 지표는 심화 | 부분 유사 |

## 2. 플랫폼 검증·승인

### Amazon과 유사한 심화 정책

Amazon은 판매자가 쿠폰을 제출한 후 검토를 거쳐 활성화하는 흐름을 사용한다. 또한 상품의 판매 이력, `Was Price` 또는 최근 최저가, 할인율 등의 자격 요건을 확인한다.

심화 구현 후보:

- 판매자 쿠폰을 `PENDING_REVIEW`, `APPROVED`, `REJECTED`로 관리한다.
- 검토 완료 전에는 고객에게 Clip·적용할 수 없게 한다.
- 가격 이력, 최근 최저가, 재고, Offer 상태를 검증한다.
- 거절 사유와 검토자·검토 시각을 기록한다.
- 가격이나 Offer 상태가 변경되면 활성 쿠폰의 자격을 재검증한다.

### 현재 P4와 다른 부분

현재 기본 과정은 판매자 쿠폰의 플랫폼 검증·승인을 하지 않고, 요청 형식·권한·Offer 소유권만 확인한 뒤 자동 적용한다. 따라서 현재 구현은 Amazon 운영 절차와 `비유사`하다. 플랫폼 검증은 심화 과정에서만 추가한다.

## 3. 예산과 동시성

### Amazon과 유사한 정책

Amazon은 쿠폰 예산을 설정하고, 고객 할인액을 예산에서 차감한다. 공개 안내에 따르면 쿠폰 예산의 80%가 소진되면 신규 노출을 중단하고, 이미 쿠폰을 적용한 고객의 결제 처리 때문에 예산을 초과할 수 있다. 쿠폰 운영 비용은 고객 할인 예산과 별도로 부과될 수 있다.

심화 구현 후보:

- `budget`: 누적 할인 예산
- `spentAmount`: 확정된 누적 할인 금액
- `reservedAmount`: 주문 처리 중 예약 금액
- 주문 적용 시 예산을 예약하고, 결제 확정 시 확정한다.
- 결제 실패·주문 취소·환불 시 예약 또는 확정 금액을 복원한다.
- 동시 주문에서 예산을 초과하지 않도록 원자적 갱신과 멱등 처리를 적용한다.

### 현재 P4와 다른 부분·확인 필요

- 예산 필드와 예약·확정 상태는 Amazon의 내부 데이터 모델을 그대로 옮긴 것이 아니라 P4의 설계 후보이다.
- Amazon의 80% 중단, 결제 대기 시간, 초과 허용 범위는 마켓과 정책 변경에 따라 달라질 수 있으므로 현재 P4의 필수 규칙으로 채택하지 않는다.
- 쿠폰 운영 수수료는 현재 P4의 할인 예산에 포함하지 않는다. 수수료를 도입하려면 별도 결제·정산 정책이 필요하다.

## 4. 대상 고객군·중복 적용

### 대상 고객군

Amazon에는 Prime 회원 전용 쿠폰과 같은 특정 프로그램이 있다. 따라서 고객군을 제한하는 쿠폰 자체는 `부분 유사`하다. 다만 신규 고객, 재구매 고객, 회원 등급, 장바구니 이력 등의 세그먼트를 일반 쿠폰의 공통 기능으로 제공한다는 현재 P4의 후보 목록은 Amazon 기본 쿠폰 정책과 동일하다고 볼 수 없다.

심화 구현 후보:

- Prime과 유사한 회원 등급 대상 조건
- 신규 고객·재구매 고객·브랜드 고객군 조건
- 고객군별 Clip·사용 자격 검증
- 고객군 조건 변경 시 기존 Clip의 처리 기준

### 중복 적용

Amazon은 쿠폰 외에도 Percentage Off, BOGO, Lightning Deal, Best Deal, 가격 할인 등 별도 할인 수단을 운영한다. 여러 할인 수단이 동시에 노출될 수 있으므로 중복 할인 가능성을 관리해야 한다. 그러나 모든 조합의 우선순위와 합산 방식이 공개된 단일 공통 규칙은 확인하기 어렵다.

따라서 다음은 `부분 유사` 또는 `확인 필요`로 둔다.

- 동일 상품에 대한 쿠폰 간 중복 적용
- 쿠폰과 가격 할인·프로모션·Deal의 동시 적용
- 중복 시 할인 우선순위
- 최대 할인 금액과 최종 결제 금액 하한

현재 P4는 서로 다른 상품에 대한 쿠폰 최대 5개 적용을 기본으로 지원한다. 동일 상품에 여러 쿠폰을 중첩하거나 쿠폰과 다른 프로모션을 조합하는 규칙은 심화 사항으로 남긴다.

## 5. 활성 쿠폰 수정 정책 비교

현재 P4는 `ACTIVE` 상태에서 `validUntil`만 수정할 수 있고 할인 정책·대상 Offer·이름은 수정할 수 없다. 이는 쿠폰 변경을 제한한다는 점에서는 운영상 안전하지만, Amazon이 활성 쿠폰의 할인액 상향 수정을 허용한다고 공지한 정책과는 `비유사`하다.

향후 Amazon과 유사하게 변경하려면 다음을 별도 결정해야 한다.

- 할인액 상향만 허용할지
- 할인액 하향과 대상 Offer 변경도 허용할지
- 변경 시 재검토가 필요한지
- 이미 Clip한 고객에게 변경된 할인액을 적용할지

현재 기본 요구사항에서는 기존 P4 규칙을 유지한다.

## 6. 사용 통계

Amazon Seller Central에는 쿠폰 운영을 확인할 수 있는 관리 화면이 있다. 따라서 Clip 수, 사용 수, 할인 금액 등을 판매자 화면에서 확인하는 방향은 `부분 유사`하다.

다만 Amazon 내부 대시보드의 정확한 집계 기준과 공개 API 데이터 모델은 이 문서에서 확정하지 않는다. 다음을 심화 후보로 둔다.

- 기간별 Clip 수
- 쿠폰 사용 수와 사용률
- 확정 할인 금액
- 쿠폰 적용 주문 수와 매출
- Offer별 사용 현황
- 취소·환불로 인한 복원 금액

통계 API는 다음과 같다.

`GET /api/v1/coupons/{couponId}/statistics`
